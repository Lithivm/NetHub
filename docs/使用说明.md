# NetHub —— 把内网流量透明地送进隧道

给指定的网段装一条**隐形代理**：应用零改动，只有目标落在你配的网段里的 TCP 连接会被内核层接管，
经你自己的上游代理转发出去。

替代「Proxifier + 两个 gost 脚本」这一套 —— 一个进程管链路、一个内核驱动管拦截、一个界面管规则。

- **应用零改动**：浏览器、数据库客户端、Navicat、业务客户端、任何按 hosts 解析的程序都不用配代理
- **规则形状对齐 Proxifier**：一条规则 = 名字 + 一组目标 + 走哪个链；自上而下匹配、命中即止
- **自带代理客户端**：`socks5` / `socks5+tls` / `socks4` / `http` / `https`，**不需要装 gost**
  旧 gost 的 `.bat` 可以在界面里直接导入（只取其中的上游地址）
- **界面**（Wails + WebView2，手写前端）：实时日志、链路自检、与 Clash 共存检测、深/浅主题

## 快速开始

1. 从 [Releases](https://github.com/Lithivm/NetHub/releases) 下载 `NetHub.zip`，解压到任意目录
2. **先让安全软件放行驱动** —— 火绒 / 360 / 腾讯管家默认会拦 `WinDivert64.sys`：
   在安全软件里信任 `nethub.exe` 和 `WinDivert64.sys`，然后**重启安全软件**。
   白名单是启动时读进内存的，不重启不生效；漏了这步的表现是日志反复报
   `Insufficient system resources exist to complete the requested service`（即 **1450**）
3. 双击 `nethub.exe`（会请求一次管理员权限，内核拦截需要），界面起来后**在界面里配置**：
   到「隧道链路」页填上游地址 → 到「路由规则」页加一条规则（网段 → 走哪条链）
   → 回顶部点「启动服务」。
   也可以直接改程序目录里的 `config.yaml`（字段见下一节；模板见 `config.yaml.example`），两者完全等价。
4. 可选：`nethub.exe -autostart` 注册开机自启（计划任务 + 最高权限，**静默提权、不弹 UAC**），
   取消用 `nethub.exe -no-autostart`

> 首次启动时内置配置只有一条**上游为空**的示例链 `proxy-a`，所以「启动服务」会失败并告诉你要填 forward ——
> 这是故意的（不预置任何真实环境）。把上游填上就能启动。

**运行要求**：Windows 10 / 11 x64（需 WebView2 运行时）、管理员权限。

## 配置 `config.yaml`

```yaml
relay: 127.0.0.1:0        # relay 监听地址；端口写 0 = 自动分配（推荐）

chains:                   # 每条链 = 一个上游代理（可填多个做故障转移/负载均衡）
  - name: proxy-a
    forward: socks5+tls://YOUR-HOST:10080?auth=YOUR_BASE64_OF_user:pass
    note: 内网 A 段走这条         # 备注，随便写，会显示在规则页的「说明」列
  - name: proxy-b
    forwards:                # 多个上游：前面的坏了自动换下一个
      - socks5+tls://YOUR-HOST-A:33001?auth=YOUR_BASE64_OF_user:pass
      - socks5+tls://YOUR-HOST-B:33002?auth=YOUR_BASE64_OF_user:pass
    strategy: failover       # failover(默认) | round(轮询) | random(随机)
    probe: 30s               # 健康探测间隔：只探到代理这一段；off = 关

routes:                   # 一条规则 = 一个动作挂一组目标
  - name: 内网 A 段            # 规则名，可省略
    targets:                 # 目标可多个：任一命中即算这条规则命中
      - 10.0.0.0/24          # CIDR 或单个 IP（单 IP 会自动存成 /32）
      - 10.0.1.0/24
    chain: proxy-a           # 动作①：命中就走这条链
  - name: 本机网段直连         # 动作②：chain 写 direct = 直连（不走代理）
    targets:
      - 192.168.1.0/24       # 本机所在的局域网：同事机器/打印机/共享盘
    chain: direct
  - name: 排除更新端口         # 端口条件：这个网段走隧道，但 7680 直连
    targets:
      - 10.0.0.0/24
    ports:                   # 留空 = 任意端口；可写 443、8000-9000
      - 7680
    chain: direct
  - name: 拉黑某个上报地址      # 动作③：chain 写 block = 阻断（丢弃 + 回 RST）
    targets:
      - 10.9.9.9
    chain: block
  - name: 内网 B 段
    targets:
      - 192.168.100.0/24
    chain: proxy-b

hosts:
  manage: false           # true = 由本程序维护 hosts 里的标记区块（你的手写内容不受影响）
  entries:                # 每行一条：内网IP 域名
    - 10.0.0.10 app.example.com

ui:
  theme: light            # light | dark
```

**上游 URL 支持的写法**（与 gost 兼容，旧脚本里的地址可以直接拿来用）：

| 写法 | 说明 |
|---|---|
| `socks5+tls://host:port?auth=<base64(user:pass)>` | 最常见的写法（gost 风格） |
| `socks5+tls://user:pass@host:port` | 凭据写在 userinfo |
| `socks5://` / `socks://` / `socks5h://` | 明文 SOCKS5（后两个是别名） |
| `socks4://` / `socks4a://` | 对端只提供 SOCKS4 时用 |
| `http://` / `https://` | HTTP CONNECT 代理（可带 `user:pass@`） |
| 末尾加 `&secure=true` | 校验上游证书；**默认不校验证书**（与 gost 的 socks5+tls 默认行为一致） |

**规则怎么理解**：自上而下匹配、命中即止，所以**顺序就是优先级** ——
先写窄网段、后写宽网段可以给某些主机单独走另一条链；一条规则里的多个目标共享同一个位置。
完全相同的目标不允许出现在两条规则里（那条永远轮不到，程序会拒绝保存并指出是哪条规则占用了）。

**不确定顺序怎么排？界面上有三个帮手**：

- **「按最具体优先排序」**：前缀长（`/32`）与带端口条件的自动排前面，同具体程度保持原有先后 —— 点一下就不用手工上下调
- **「查一个 IP」**：填 `10.0.0.5` 或 `10.0.0.5:5432`，直接告诉你命中第几条规则、走哪条链、该链上游健不健康、
  目标上次巡检通不通，以及**还被哪几条规则匹配但被抢先了**
- **影子目标警告**：手写配置里如果有目标被前面的规则完全覆盖（永远不会生效），
  规则表会标 `⚠ N 个目标被前面的规则覆盖`，悬停看是哪几个

**动作有三种**：**走某条链**、**「直连」**（`chain: direct`，界面上选「直连（不走代理）」）、
**「阻断」**（`chain: block`，直接丢弃，并回一个 RST 让应用**立刻**看到连接被拒）。

直连的包不改写、不进隧道，原样交给系统转发 —— 该给**本机所在的局域网**用：
同事的机器、打印机、共享盘、内部管理页。这些目标本来就在你本地线路上，
送进隧道反而不可达（异地代理到不了你的局域网），而且白占隧道带宽。
阻断用于“就是不让它出去”的场景：不该访问的后台上报、扫描源、广告域名对应的内网地址等。

- 别忘了配它：规则页填目标时点一下「**填本机网段**」按钮，把本机网段直接填进去
- 直连规则的目标只要不和隧道网段重叠，就**不会**进内核过滤器 —— 等于零开销
- 若某台机器既在隧道网段里、又想直连（例如 `10.10.10.0/24` 整体走隧道，
  但 `10.10.10.102` 是本地同事机器），把直连规则**放在隧道规则前面**即可

**端口条件**（规则的 `ports`，留空 = 任意端口）：填了就要求「**目标命中 且 端口命中**」。
三个常见用法：

| 想干的事 | 怎么写 |
|---|---|
| 某个端口不要走隧道（比如 Windows 更新的 7680 老是报错） | 前面加一条直连规则：`targets: [10.0.0.0/24]` + `ports: [7680]` |
| 同一个地址不同端口走不同链 | 前面窄的那条带 `ports`，后面宽的那条不带（如 `10.0.0.5:443 → 链 A`、`10.0.0.5:5432 → 链 B`） |
| 只把业务端口放进隧道（暴露面更小） | 规则写 `ports: [443, 5432]`，其余端口自然不走我们 |

写法：单个端口 `443`、区间 `8000-9000`（也接受 `8000~9000`；写反了自动换）。
端口条件同样会写进内核过滤器 —— 没列到的端口在驱动层就被放行，**零开销**。

**多上游与健康探测**：一条链可以填多个上游（`forwards`），用 `strategy` 决定怎么挑：

| 策略 | 行为 |
|---|---|
| `failover`（默认） | 按顺序试，第一个能用的就用；前面的拨不通自动换下一个 |
| `round` | 轮询，把连接均摊到多条上游 |
| `random` | 随机挑一条 |

健康探测（`probe`，默认 30s，`off` 关）只测**到代理这一段**（TCP + TLS 握手），
不会去访问任何内网业务目标。探到不通的上游会被排到最后；恢复后自动回来。
除了主动探测，**真实连接的成功/失败也会记进健康表**（被动探测），所以即使关掉探测，
错路也会自己跷到后面去。界面上每条上游一个小圆点：绿=可用、红=不可用、灰=待探测。

**什么时候需要重启**：改名字/目标/链/规则顺序都是**即时保存、即时生效**；
但**新增网段**要在界面上点一次「重启」才生效（内核过滤器在启动时按网段展开），
`relay` 和 `hosts.manage` 同样需要重启服务。

## 界面

| 页 | 内容 |
|---|---|
| **运行日志** | 实时日志 + 链路自检 + 打开日志目录 |
| **隧道链路** | ≈ Proxifier 的 *Proxy Servers*：增删改排序；一条链可填多个上游（故障转移/负载均衡）+ 健康探测；可从旧 `.bat` 导入 |
| **路由规则** | ≈ Proxifier 的 *Rules*：一条规则 = 名字 + 一组目标 +（可选）一组端口 + 动作（走哪条链 / 直连 / 阻断） |
| **设置** | 与 Clash 共存检测 / hosts 接管 / 开机自启 / 导出配置 / 文件位置 |

右上角切深色 / 浅色（会记住）。**点 × 是最小化到托盘，服务继续跑**；真退出走托盘右键 → 退出。
双击托盘图标唤回窗口；启动完成、链路异常这类事件会弹系统通知。

## 常见问题

| 症状 | 怎么办 |
|---|---|
| 报 **1450**、或有 `WinDivert 打开失败(第 N/6 次)` 重试行 | 安全软件拦了驱动。信任 `nethub.exe` + `WinDivert64.sys`，**并重启安全软件**；反复加载/卸载驱动后仍报 1450 就重启系统 |
| 程序起来了但没拦到任何连接 | 看日志里有没有 `当前不是管理员权限` —— 内核拦截必须管理员 |
| 内网连不上，日志有 `已接管` | 界面点「链路自检」：它绕过内核拦截、直接走上游发一次真实请求 |
| 内网**用 IP 能通、用域名不通** | 域名解析没有指向内网 IP（多数是 Clash 这类工具用自己的 DNS）。见下节 |
| 想单独验证上游 / 检查与代理软件冲突 | `nethub.exe -test-upstream`、`nethub.exe -clash-check`（都不需要管理员，只读） |
| 改了网段没生效 | 界面点「重启」（见上文"什么时候需要重启"） |
| 文件都在哪 | 界面「设置 → 文件位置」有配置与日志的完整路径 |

**和 Clash / 其他代理软件共存**：本程序不改系统代理、不动路由表，所以不抢设置。
但要注意四点：

- **内网请求不能经过对方的 DNS** —— 只要流量被交给对方按域名解析，它就看不到系统 hosts，
  永远解析不到内网地址。用**内网 IP** 访问是通的，用**内网域名**就会坏
- **不要把对方开成 TUN 模式**：TUN 会写 `0.0.0.0/1` + `128.0.0.0/1` 的默认路由，把内网段一起吞掉
- **对方用 PAC 模式时，系统的"绕过地址"列表不生效** —— 内网域名会被交给对方解析，必坏；
  要让绕过列表生效就用它的「普通系统代理」模式，或干脆让浏览器不走代理
- **不要同时用 Proxifier**：两套内核层拦截会互相干扰

## 卸载

```powershell
nethub.exe -no-autostart     # 先移除开机自启
# 托盘右键 → 退出，然后整个文件夹删掉即可
sc stop WinDivert            # 可选：清掉驱动服务残留（需管理员）
sc delete WinDivert
```
