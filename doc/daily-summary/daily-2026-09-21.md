### 修复（都是实测出来的）

8. **snzyy 类"无冒号 auth"**：穷举 9 种写法后确认 gost 语义是「整个值 = 用户名、口令空」——以前猜反了，这类上游一直认证失败
9. **DNS 接管后记录真实 IP**：以前不记 → ①通配规则永远显示"还没学到 IP"（像坏了）②应用用缓存真实 IP 回访时匹配不上
10. **启动 16.3 秒 → 0.31 秒**：逐段打点定位真凶是"读 Windows DNS 缓存"（16.3s，且本次读到 0 条有用名字）→ 挪后台，结果经动态过滤器补上
11. **深色告警条选择器 `body.theme-dark` 从未生效**（主题挂在 `<html data-theme>` 上）→ 深色模式一直在用浅色底，又亮又暖 → 改 `[data-theme="dark"]`
12. **7680 直连规则插错位置**：被前面的 `HIS 主链路` 全盖住、永远轮不到（等于没加）；挪到最前并用引擎同款匹配器做**确定性验收**（192.168.1.5:7680→直连、同 IP 的 445→仍走 etyy）
13. 探活优先用**规则里写死的单个 IP**（以前只找 hosts，xaby-dev 的真实目标就写在规则里却被跳过）；多个时逐个试到底
14. 链路自检"找不到可探测的真实主机"由 WARN 降为 INFO；进程定位不到的失败不再打 ERROR，也不再打误导性的 `PID 0`
15. **放宽规则校验**：不再拦"目标被别的规则占了"、"引用了不存在的链"（真实现场大量合法重叠；引擎运行时本就会报）→ 改为保存后提示
16. 配置**导出（含凭据）→ 清空 → 重新导入**加回环测试（走真实导出/导入函数，逐字段比对 + 坏配置不许动现场）
