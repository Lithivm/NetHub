### 排查（驱动被杀软拦）

1. 火绒 1450 定性到根因：火绒 6.0「漏洞驱动拦截」按文件把 `WinDivert64.sys` 判成
   `BYOVD_network_redirect` 在内核层拒加载（`log.db-wal` 的 modblock 记录为证）
2. 正解 = 系统防护 → 漏洞驱动拦截 → **例外驱动**；**只加杀软信任区不管用**（这条是本次纠正的关键）
3. 产品化：引擎 `ErrDriverBlocked` 哨兵（按 1450/1275 错误码判，不认中文消息）→ 常驻告警条 +
   诊断页「安全软件白名单」卡 + 诊断包里的白名单清单

### 上游与内核（新增能力）

13. 上游协议适配器边界（T13）：`Proxy` 接口 + 注册表，加协议 = 加一个文件；**对外 API 一字未改**；
    契约测试 6 条 × 4 协议（当场抓到 socks4 双栈域名取 `ips[0]` 的真 bug）
14. mTLS 客户端证书：`?cert=&key=`，证书在**解析期**加载；**不借用 `mtls` 这个词**（gost 的 mtls 是 multiplexed TLS，撞名）
15. WinDivert 加两层（T15/T16）：SOCKET 层 `connect` 事件按端口补进程名；REFLECT 层汇总
    "本机还有谁在用 WinDivert"（启动汇总 + 新出现时告警 + 进诊断包）
16. DNS 泄漏面收口：非 A/AAAA 记录（SVCB/HTTPS 的 `ipv4hint`）本该走链的名字一律答空（dev 实测 4 项）

### 关键修复（进程名 60% → 0%）

17. 真因不是 SOCKET 层，而是 **`missRefillEvery` 定义了却从没被引用** —— 查不到进程时的重读节流
    实际用的是 `interval*2`（1 秒），同一秒内的一批新连接只有第一个能触发重读
18. 窗口收到 50ms，本机同负载实测三档：**1 秒 60% → 300ms 42% → 50ms 0%（12/12 全有名字）**；
    并把这三组数字写进常量注释、加测试钉住"过了窗口必须重读"
19. 修 `reflectwatch` 一个真 bug：把"2 秒后汇总"的定时检查写在**阻塞的 `Recv` 之后**，
    而 REFLECT 重放完已有句柄就安静了 → 汇总永远不执行（一行都打不出来）
20. 修上一个界面 bug（v0.5.1）：进设置页后「运行日志」变灰 —— tab 高亮**两套机制**（字变白 + 蓝胶囊）
    由同一个循环驱动，而胶囊函数在"没有选中项"时**提前返回**，胶囊原地不动 → 灰字压在蓝胶囊上；
    改成没有选中项时胶囊收起来

### 选型问答

25. SQLite 评估：先量数据体量 —— 持久化的只有 `config.yaml` **2.6 KB / 80 行** + 有上限的文本日志
    （单文件 8 MB × 留 5 份），连接表/名字表/假 IP 池**全在内存且已有界**
26. 结论**暂不引入**：没有一条 `SELECT ... WHERE` 的场景；纯 Go 驱动让二进制 +5~8 MB（整个发布包才 5.9 MB）、
    cgo 驱动要 CGO + 交叉编译变难；且日志一进 DB，"把日志直接发给同事/agent 读"这条路就断了
27. 写下四个触发条件（要留存历史连接并能查 / 要统计报表 / 要跨进程跨重启共享 / 名字表要持久化），
    以及判据：**"要存"用文本（JSONL 按天分文件），"要查"才上库**
